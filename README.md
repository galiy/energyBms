# EnergyBMS

Реверс-инжиниринг протокола обмена BMS-устройства **EMU1101** (8S–16S LFP/NCM,
100–300 A) производства **Shanghai Enjie Electronic Technology Co., Ltd.**
(бренд **N ENERGY** / **EN**, 上海恩阶电子科技有限公司).

Устройство общается с инвертором по CAN/RS-485, а с приложением — по Bluetooth
Low Energy. Цель проекта — полностью восстановить «верхний» протокол платы
(тот же кадр, что идёт по RS-485 и через BLE-мост BT2), чтобы уметь читать
телеметрию и писать параметры/режимы без фирменного ПО.

## Статус

**Протокол восстановлен и подтверждён двумя независимыми источниками:**
читаются телеметрия, защиты и блок из 169 байт параметров; восстановлены
форматы чтения и **записи** параметров, флагов, режимов, времени, SN и
расписания. Идентифицировано семейство (YD/T 1363 / Pylontech / PACE «CID»).

## Кратко о протоколе

```
Запрос:  7E | 10 | ADR | 46 | CID2 | LEN(2) | INFO | CHKSUM(2) | 0D
Ответ:   7E | 14 | ADR | CID2 | RTN | LEN(2) | INFO | CHKSUM(2) | 0D
```

- Полная длина кадра = `10 + LENID`; в ответе `LENID = frame[5]<<8 | frame[6]`,
  `INFO` — с байта 7 (уточнено живым захватом 2026-09-30; ранее в описаниях
  ответа байт `RTN` был пропущен).

- Транспорт BLE: сервис `0000ff00`, запись `0000ff02` (h `0x14`), уведомления `0000ff01` (h `0x11`).
- RS-485: baud **19200**, тот же кадр.
- `CID1 = 0x46`, `SOI = 0x7E`, `EOI = 0x0D`; ключевые команды: `0x42` телеметрия,
  `0x44` защиты, `0x47`/`0xA1` чтение/запись параметров, `0x45` управление,
  `0x49` запись одного параметра/флага, `0xA6` выбор CAN-протокола.
- Контроль: CRC-16/CCITT (приложение) либо 16-битная сумма-дополнение
  (ПО Upper Computer) — подробности и открытый вопрос в `PROTOCOL.md` §3.3/§11.

Подробно — в [`PROTOCOL.md`](PROTOCOL.md).

## Правила работы

- Приватные данные и секреты — только в `.kilo/` (в `.gitignore`).
- BT-адаптер сервера для опроса **не трогать** (только пассивный скан/подключение).
- История изменений ведётся в контексте этой папки; коммиты — только по запросу.
