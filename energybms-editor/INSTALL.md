# EnergyBMS Editor 0.1.1 — установка и настройка

Портативное GUI-приложение для BMS Enjie EMU110x: чтение телеметрии,
состояния/защит, параметров и редактирование/сохранение параметров через
RS485 (COM или прозрачный TCP-шлюз) либо BLE.

Платформы: **Windows x64**, **Linux x64**, **macOS (Apple Silicon, arm64)**.
Настройки соединения хранятся в `energybms_editor.json` **рядом с запускаемым
модулем** — приложение и конфиг можно носить на флешке.

---

## 1. Готовые сборки (рекомендуется)

Скачайте артефакт для своей платформы со страницы **Releases**:

| Платформа | Файл | Запуск |
|-----------|------|--------|
| Windows 64 | `energybms-editor-<версия>-win64.exe` | двойной клик (при первом запуске SmartScreen → «Подробнее» → «Выполнить») |
| Linux 64 | `energybms-editor-<версия>-linux64` | `chmod +x energybms-editor-<версия>-linux64 && ./energybms-editor-<версия>-linux64` |
| macOS (Apple Silicon, arm64) | `energybms-editor-<версия>-mac-arm64.zip` | распаковать, перетащить `energybms-editor.app` в «Программы» |

Приложение портативно: рядом с бинарником появится `energybms_editor.json` с
последними настройками. Перенос — просто скопировать бинарник (и, при желании,
JSON) на другую машину.

### Права доступа к портам/устройствам

- **Windows:** драйверы USB-RS485/COM ставятся производителем адаптера; порт
  виден как `COMx`. Для BLE нужен Windows 10+.
- **Linux:** пользователь должен иметь доступ к порту. Добавьте себя в группу
  `dialout` (или дайте права на `/dev/ttyUSB*`):
  ```sh
  sudo usermod -aG dialout "$USER"   # затем перелогиниться
  ```
  Для BLE нужен работающий **BlueZ** и запущенный `bluetoothd`.
- **macOS:** для BLE при первом подключении разрешите доступ к Bluetooth
  (Системные настройки → Конфиденциальность и безопасность → Bluetooth).
  USB-Serial обычно виден как `/dev/tty.usbserial-*`.

## 2. Запуск из исходников

Требуется Python 3.10+ (рекомендуется 3.12).

```sh
git clone https://github.com/galiy/energyBms.git
cd energyBms/energybms-editor
python -m pip install -r requirements.txt
python run_editor.py
```

Windows: `py -3 run_editor.py`. Linux/macOS: `python3 run_editor.py`.

## 3. Настройка соединения

Кнопка **«Соединение…»** — выбрать транспорт:

### TCP (прозрачный RS485/RS232-шлюз)
- **Host / Port** — адрес и TCP-порт шлюза.
- **Порт BMS**:
  - `host-RS485` (п. 10.2, 19200) — телеметрия, состояние, **параметры**, время, SN;
  - `RM485` (п. 10.1, 9600) — только телеметрия/состояние/инфо (параметры недоступны).

### Serial (COM / tty)
- **Порт** — `COMx` или `/dev/ttyUSB0` / `/dev/tty.usbserial-*`.
- **Baud** — 19200 (host-RS485) или 9600 (RM485).
- Порт BMS — как выше.
- Настройки подхватывают список доступных COM-портов автоматически.

### BLE
- **Сканировать…** — кнопка запускает поиск в фоне; выберите устройство из
  списка (BMS обычно называется `BP00`), либо впишите имя/адрес вручную.
- Сервис `ff00`, запись `ff02`, уведомления `ff01`.

Кнопка **«Чтение»** опрашивает все блоки, поддерживаемые выбранным каналом, и
раскладывает их по вкладкам: «Телеметрия», «Состояние/защиты», «Параметры»,
«Инфо / SN». Последние настройки автоматически сохраняются в JSON.

## 4. Редактирование параметров

1. На вкладке **«Параметры»** нажмите **«Редактировать»** — поля значений и
   флажки бит-групп станут доступны.
2. Введите значения. Нечисловое или выходящее за диапазон поле подсветится
   красным; кнопка **«Сохранить»** активна только при наличии изменений и
   отсутствии невалидных значений.
3. **«Сохранить»** покажет список изменений «Было → Новое». После подтверждения
   изменения записываются в BMS командой `0xA1` (весь блок 169 Б), затем
   устройство перечитывается для контроля.

> **Внимание.** Проект работает по правилу «в BMS ничего не писать, только
> чтение» (`AGENTS.md`). Запись `0xA1` запускайте против живого устройства
> **только по отдельному явному разрешению**. По умолчанию пользуйтесь «Чтением».

## 5. Сборка из исходников

### Локально (текущая ОС)
PyInstaller — **не кросс-компилятор**: локально собирается только бинарник под
текущую ОС/архитектуру. С Linux собирается только `linux64`; для `win64` и
`mac-arm64` нужны соответственно Windows и macOS (используйте CI ниже).

```sh
pip install -r requirements.txt pyinstaller
cd energybms-editor
pyinstaller --noconfirm --clean --onefile --windowed \
    --name energybms-editor \
    --hidden-import serial --hidden-import serial.tools.list_ports \
    --hidden-import bleak --collect-all bleak \
    run_editor.py
```
Результат — в `energybms-editor/dist/`.

### Все платформы через CI
Файл `.github/workflows/release.yml` собирает win64/linux64/mac-arm64 на
GitHub Actions при пуше тега `v*` и публикует релиз:
```sh
git tag v0.1.1
git push origin v0.1.1
```

## 6. Диагностика

- **«нет ответа»** — неверный порт/baud/роль (host vs RM485) или адрес шлюза.
- **RM485 не отдаёт параметры** — это нормально: `0x47` там `RTN=04`, используйте
  host-RS485.
- **BLE не находит устройство** — включите Bluetooth, проверьте права (Linux
  BlueZ / macOS разрешение), повторите скан.
- **Настройки не сохраняются** — каталог рядом с бинарником недоступен для
  записи (например, Program Files); запустите приложение из другой папки.
