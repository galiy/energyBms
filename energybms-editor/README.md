# EnergyBMS Editor

Портативное GUI-приложение для BMS Enjie EMU110x: просмотр телеметрии,
состояния/защит, параметров и **редактирование/сохранение параметров** через
RS485 (COM или прозрачный TCP-шлюз) либо BLE.

- Платформы: **Windows x64**, **Linux x64**. GUI на PySide6 (Qt6), не web.
- Портативность: приложение и все настройки — в одной папке; последние
  применённые настройки соединения сохраняются в `energybms_editor.json` рядом
  с запускаемым модулем.

## Установка зависимостей

```sh
pip install -r requirements.txt
```

## Запуск

```sh
python run_editor.py          # Windows
python3 run_editor.py         # Linux
```

Другой вариант (как пакет):

```sh
python -m energybms_editor.main
```

## Интерфейс

1. **Соединение…** — вариант подключения:
   - **TCP** — прозрачный RS485/RS232-шлюз (host/port + роль порта BMS);
   - **Serial** — COM (Windows) или `/dev/tty*` (Linux) + baud;
   - **BLE** — имя/адрес устройства (кнопка «Сканировать…»).
   Настройки применяются и сохраняются в JSON.
2. **Чтение** — опрашивает все блоки, поддерживаемые выбранным каналом:
   - RS485 host: `0x42` телеметрия, `0x44` состояние/защиты, `0x4F`, `0x51`,
     `0x47` параметры, `0x4D` время, `0xA4` SN;
   - RS485 RM485: `0x42`, `0x44`, `0x4F`, `0x51` (параметры недоступны);
   - BLE: `0x51`, `0x61`, `0x62`, `0x47`.
3. Каждый блок — **на своей закладке**: «Телеметрия», «Состояние/защиты»,
   «Параметры», «Инфо / SN».

## Редактирование параметров

- Таблица параметров **заблокирована** от изменения.
- Кнопка **«Редактировать»** открывает редактирование (поля значений и
  чекбоксы бит-групп).
- **Валидация:** нечисловое или выходящее за диапазон значение подсвечивается
  красным; кнопка **«Сохранить»** неактивна при отсутствии изменений или при
  наличии невалидного параметра.
- **«Сохранить»** открывает окно со списком изменений «Было → Новое»; после
  подтверждения изменения пишутся в BMS командой `0xA1` (read-modify-write,
  весь блок 169 байт) и устройство перечитывается для контроля.
- **«Отменить изменения»** возвращает прочитанные значения.

> Запись в BMS выполняется только по явному подтверждению пользователя.
>
> **Правила проекта (`../AGENTS.md`):** «В BMS ничего не писать. Только чтение»;
> операции со шлюзом `192.0.2.77` ограничены parity через web-ui. Команда
> записи `0xA1` реализована по прямому запросу на разработку редактора, но
> запускать её против живого устройства можно **только с отдельного явного
> разрешения**, отдельно от правил. По умолчанию используйте только «Чтение».

## Портативная сборка (опционально)

```sh
pip install pyinstaller
pyinstaller --noconfirm --onefile --windowed \
    --name energybms-editor run_editor.py
```

Готовый файл появится в `dist/`. JSON настроек создаётся рядом с исполняемым
файлом. Для BLE на Linux нужен работающий BlueZ; на Windows — Windows 10+.

## Архитектура

- `protocol.py` — единая логическая модель + два wire-кодека: `PaceCodec`
  (ASCII PACE, RS485) и `BleCodec` (бинарный, CRC-16/CCITT).
- `params.py` — таблица 87 параметров + 8 бит-групп, кодирование/декодирование
  169-байтного блока.
- `telemetry.py` — декодеры `0x42`/`0x44`/`0x51`/`0x4D`/`0x61`.
- `transports.py` — Serial / TCP / BLE (только байты).
- `link.py` — связка транспорт+кодек, чтение и запись `0xA1`.
- `main_window.py`, `params_tab.py`, `connect_dialog.py` — UI.
- `config.py` — портативный JSON рядом с запускаемым модулем.

Подробности архитектуры — `../energyBms-editor.md`. Протокол — `../protocol-485.md`,
`../protocol-BLE.md`.
